    System Evolution

    CAS is evolving from a decision-driven architecture documentation system into a continuously governed architecture intelligence platform. Operational changes include the CAS Workflow Execution Model, where the Runner orchestrates, workflows reason, Knowledge Providers access knowledge, and prompts act as contracts. The Knowledge Provider abstraction decouples workflows from repository structure, while runtime onboarding converts prompt-native workflows into runtime-native capabilities. Architecture Work is now the authoritative architectural backlog, with generated artifacts deriving planning state rather than competing with it. The Governance Portal and alignment summary frontmatter promotion improve governance visibility and machine-readable alignment state. Accepted decisions establish a Runtime Capability Inventory, target-project evidence isolation, forensic architecture-state diagnostics, deterministic generator contracts, and provider-agnostic LLM gateways. Proposed work extends this into automated detect-analyse-execute governance, CI enforcement of CAS skills, project-specific knowledge templates, and continuous governance runtime capabilities. The system is also moving toward code intelligence, architecture alignment, business-intent traceability, knowledge graphs, and portfolio intelligence, but these remain proposed Architecture Work and must not be treated as accepted system state until governance approval.

    Intent & Direction

    The project-scoped vision points toward an Architecture Intelligence Platform that connects business intent, architecture, code, and decisions. Its forward direction includes business-layer integration, code intelligence, continuous intent-versus-reality alignment, ReasoningOps and GovernanceOps as continuous operational capabilities, external ecosystem ingestion, and interactive Architecture Intelligence Maps. The guiding intent is to extend existing CAS primitives rather than rewrite them, keep decisions central, prefer traceability over abstraction, retain human governance authority, and validate capabilities through real use cases. Near-term direction should remain anchored in proposed Architecture Work such as the core orchestration ADR, knowledge template validation, CI skill enforcement, business intent traceability, and the automated governance loop. Longer-horizon themes such as portfolio intelligence, external ecosystem integration, and interactive knowledge graphs should remain distinguished from governance-approved system commitments.
