    Reference Architecture: Schema-Enforced Domain Contracts

    Purpose & when to use this

    Schema-Enforced Domain Contracts establishes a strict validation perimeter around non-deterministic compute steps—such as Large Language Model (LLM) agents, heuristics, or external ingestion pipelines—before their generated outputs are permitted to transition domain state, execute downstream mutations, or seed subsequent execution context.

    When to use this

    • When integrating stochastic or generative components (e.g., LLM prompts, agent workflows) into enterprise workflows that require deterministic downstream reliability.
    • In distributed multi-agent systems where context, intermediate results, and tool invocations must adhere to uniform, immutable data structures.
    • When persisting operational domain artifacts (e.g., governance inventories, audit trails, state checkpoints) where schema drift or missing keys causes downstream computation failures.
    • At bounded context boundaries where external or loosely-typed payloads must be sanitized and converted into strongly-typed domain primitives.

    When NOT to use this

    • In purely exploratory, free-form conversational interfaces where inputs and outputs are ephemeral and possess no structured downstream consumers.
    • In high-throughput, sub-millisecond hot paths (e.g., raw network packet processing, telemetry ingestion) where deserialization and validation CPU overhead exceeds allowable latency budgets.
    • Simple internal helper scripts or ephemeral one-off utilities with zero external dependencies and trivial lifecycles.

    Components

    • Domain Contract Models (src/cas_runner/governance/models.py): Defines immutable, strongly-typed schemas (e.g., GovernanceInventory, ComplianceFinding, GovernanceHealth, GovernanceRisks, GovernanceAction) using strict validation constraints, field descriptions, and JSON schema export capabilities.
    • Contract Validation Interceptor (src/cas_runner/governance/validator.py): Acts as an anti-corruption layer intercepting unstructured or raw structured LLM outputs, executing parsing, raising actionable validation exceptions, or triggering targeted repair cycles on schema failure.
    • Compliance & Downstream Calculators (src/cas_runner/governance/engine.py): Consumes validated domain models to compute governance health scores, identify systemic vulnerabilities, and generate deterministic compliance reports without defensive nil-checking.
    • Domain State Repository (src/cas_runner/governance/repository.py): Persists and loads validated contract instances to and from durable storage, maintaining revision metadata and schema version headers.

    Technology choices

    Recommended Technologies

    • Pydantic v2 / Rust Core: Selected as the primary data modeling and validation runtime due to compiled C/Rust performance, expressive type hinting, strict mode enforcement (extra='forbid'), and native JSON Schema generation.
    • JSON Schema (Draft 2020-12): Selected as the transport and LLM prompt specification standard to guide structured outputs via JSON mode / constrained decoding.

    Alternatives Considered & Set Aside

    • Marshmallow / Attrs: Set aside due to lack of seamless native type-hint ergonomics and significantly slower serialization/validation throughput compared to Pydantic v2.
    • Raw Python Dataclasses with Manual Guards: Set aside because manual invariant checking does not scale across deeply nested domain structures and lacks automated JSON Schema synthesis for model prompting.
    • Protobuf / gRPC Structs: Set aside for intra-application runtime state due to high code-generation friction and lower flexibility in dynamic Python agent workflows, despite its strength in cross-language RPC.

    Variants

    1. Synchronous Fail-Fast Validation

    Directly validates raw LLM payloads synchronously. If validation fails, execution halts immediately with a detailed serialization traceback.

    2. Autonomous Agent Self-Correction Loop

    On validation failure, validation errors (JSON path, missing key, expected type) are converted into a corrective feedback prompt and reinjected into the LLM context for iterative re-generation up to an exhaustion threshold (typically 2-3 retries).

    3. Graceful Partial Ingestion (Quarantine Mode)

    In high-volume pipeline scenarios, invalid payloads are tagged with a schema-violation marker and directed to a quarantine storage bucket for administrative review, while valid subsets of the model are processed downstream.

    Non-functional characteristics

    Reliability

    Eliminates downstream null pointer dereferences and attribute missing exceptions by establishing an absolute boundary guarantee. Non-conforming payloads cannot enter domain persistence or analytics.

    Performance & Latency

    Validation introduces sub-millisecond CPU overhead when leveraging Pydantic v2 native Rust parsing. When employing iterative agent self-correction variants, validation errors can incur an additional LLM round-trip latency (1-3 seconds).

    Cost & Efficiency

    Reduces compound inference costs by failing invalid payloads immediately before triggering expensive multi-stage agent toolchains. Structured JSON schema prompting shrinks token output drift.

    Operability

    Validation errors emit explicit JSON-path diagnostic logs (loc, msg, type), dramatically accelerating debugging and prompt engineering triage in production.

    Anti-patterns & known pitfalls

    Permissive Extra Attributes (extra='allow')

    • Pitfall: Allowing arbitrary extra attributes in models masks LLM hallucinations and structural drift, contaminating domain persistence with junk fields.
    • Remedy: Enforce model_config = ConfigDict(extra='forbid', frozen=True) across all domain boundary contracts.

    Downstream Defensive Patching

    • Pitfall: Adding repeated getattr(), fallback None guards, or default dictionaries inside downstream business engines rather than rejecting invalid structures at the perimeter.
    • Remedy: Mandate that business engines strictly accept typed model instances, removing all defensive parsing logic from core domains.

    Direct Database Hydration from Raw LLM Dictionaries

    • Pitfall: Ingesting raw JSON responses directly into relational or document stores without passing through validation entities.
    • Remedy: Force all persistence operations through typed serialization entities.

    Adoption guidance

    Migration Path

    1. Model Definition: Define core domain entities in a centralized models module (src/cas_runner/governance/models.py) with strict field validations and constraints.
    2. Perimeter Enforcement: Wrap all agent invocation outputs and external API ingest points with model parsing calls (Model.model_validate(payload)).
    3. Downstream Refactoring: Strip defensive conditionals from downstream engines and type-annotate all consumer functions with the validated model.
    4. Schema Evolution: Implement semantic versioning on models and integrate migration transforms for persisted state.
