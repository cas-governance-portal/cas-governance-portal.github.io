    Reference Architecture: Schema-Enforced Domain Contracts

    Purpose & when to use this

    The Schema-Enforced Domain Contracts reference architecture establishes deterministic runtime verification across system boundaries, agent execution environments, and state-mutating pipelines. It ensures that generative or semi-autonomous workflows cannot ingest, propagate, or persist malformed, hallucinated, or schema-violating data into core domain repositories.

    When to use this

    • In autonomous and agentic workflows where Large Language Models (LLMs) emit structured data (actions, compliance findings, state mutations) that mutate system state or downstream storage.
    • In distributed architectures where services exchange critical domain entities requiring strict validation boundaries to prevent silent schema drift.
    • When business-critical consumers (e.g., scoring engines, health calculators, compliance dashboards) demand strongly typed guarantees with zero tolerance for missing fields.

    When NOT to use this

    • During early exploratory prototyping or disposable proof-of-concept scripts where data models are actively mutating multiple times per hour and strict validation creates undue friction.
    • For streaming unstructured text or raw conversational messaging where no downstream system relies on deterministic structure.
    • When payload ingestion is high-throughput binary streaming (e.g., audio, raw video frames) where JSON Schema/Pydantic validation introduces prohibitive deserialization overhead.

    Components

    • LLM Agent Orchestrator (src/cas_runner/agent.py): Coordinates execution passes with foundational LLMs and captures raw output text or JSON payloads for downstream processing.
    • Domain Contract Models (src/cas_runner/governance/models.py): Defines canonical entity schemas using Pydantic v2 and JSON Schema (GovernanceInventory, ComplianceFinding, GovernanceHealth, GovernanceRisks, GovernanceAction).
    • Compliance & Validation Engine (src/cas_runner/governance/compliance_engine.py): Executes programmatic boundary enforcement, handles validation errors, manages retry/re-prompt policies, and blocks invalid mutations.
    • Governance State Store (src/cas_runner/governance/store.py): Persists and indexes verified, validated domain entities, ensuring repository integrity and deterministic read-model projections.

    Technology choices

    • Recommended: Pydantic v2 / JSON Schema Core: Selected for compile-time and runtime type validation, ultra-low serialization latency via Rust-backed core, and seamless automated OpenAPI/JSON Schema export.
    • Recommended: Python TypedDict & Protocols: Selected to provide structural typing and strict static analysis support across type checkers (mypy, pyright).
    • Alternative Set Aside: Loose Dictionary DTOs / Schemaless JSON: Discarded due to lack of compile-time and runtime validation, resulting in silent failures when agents omit mandatory fields.
    • Alternative Set Aside: Marshmallow / Cerberus: Set aside due to higher runtime overhead, duplicate type definitions between classes and schemas, and lack of native modern typing integration compared to Pydantic v2.
    • Alternative Set Aside: Protocol Buffers / gRPC: Considered for binary microservices; set aside for application-level domain entities where human-readable JSON payloads, agent prompting compatibilities, and Git-based repository persistence are prioritized.

    Variants

    • Synchronous Boundary Assertion: Fails immediately upon receiving malformed input, raising an unrecoverable exception and halting pipeline execution.
    • Agentic Self-Correction Loop: Catches schema validation errors, formats validation failures into a targeted feedback prompt, and instructs the agent to fix and re-emit the payload within a configured retry limit.
    • Dual-Schema Migration Variant: Supports dual-write/dual-read versions with compatibility layers when migrating domain entities across backward-incompatible versions.

    Non-functional characteristics

    • Reliability: High. Enforces fail-safe boundaries. Prevents corrupted state from being persisted to repository state stores or read caches.
    • Performance & Latency: Microsecond-to-submillisecond overhead per validation event using Pydantic v2 Rust core; negligible compared to external network and LLM inference latencies.
    • Cost & Efficiency: Prevents downstream cascading failures and eliminates wasted processing cycles on corrupted records. When coupled with agentic correction, requires a strict re-try ceiling to avoid LLM token inflation.
    • Operability: Transparent error reporting with path-specific error objects detailing the exact offending field, expected type, and constraint violation.

    Anti-patterns & known pitfalls

    • Loose Dictionary Pass-Through: Ingesting dict[str, Any] across service or boundary boundaries without instant validation, deferring failure to deep call stacks.
    • Silent Coercion & Truncation: Silently stripping unexpected keys or coercing incompatible types without error logging, hiding agent hallucinations or contract drift.
    • Infinite Retry Reprompting: Allowing an autonomous agent to repeatedly fail validation without an escalation breaker, leading to API budget exhaustion and unbounded latency.
    • Dual Truth Schemas: Maintaining separate, out-of-sync schemas between agent prompt instructions and validation models instead of generating prompt constraints directly from code.

    Adoption guidance

    1. Starting Point: Centralize all shared entities into a dedicated governance/models package. Replace all raw dictionaries and generic objects with explicit Pydantic models.
    2. Boundary Interception: Implement validation gates directly at the input and output boundaries of external adapters (LLM responses, API controllers, repository loaders).
    3. Error Handling Policy: Configure an explicit handling policy (Immediate Fail vs. Retry Loop with max_attempts <= 2).
    4. Governance Ownership: Governed under Core Platform Architecture (domain_id: core-governance, initiative_id: agentic-integrity).
