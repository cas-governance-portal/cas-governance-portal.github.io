    Reference Architecture: Registry-Guarded Governance State Machine

    Purpose & when to use this

    The Registry-Guarded Governance State Machine establishes deterministic control boundaries over autonomous agents and programmatic workflows by intercepting all entity lifecycle state transitions and validating them against an explicit transition registry.

    When to use this

    • When autonomous agents or LLM-driven workers possess execution authority to modify, promote, or deprecate architectural or business-critical artifacts.
    • When business or governance requirements dictate strict, verifiable lifecycle phases (e.g., candidate -> under_review -> approved -> promoted) that must never be bypassed.
    • When auditability, regulatory compliance, and non-repudiation of entity status changes are mandatory.
    • When automated systems need deterministic guardrails to prevent cascading hallucinations or unauthorized state mutations.

    When NOT to use this

    • When managing transient or stateless workflows where artifacts do not persist across execution boundaries.
    • In early-stage prototyping or unstructured exploratory agent loops where dynamic, ad-hoc state creation is required without fixed governance.
    • For standard CRUD entities where state mutations carry no downstream governance, compliance, or operational risk.

    Components

    • GovernanceActionEngine (src/cas_runner/governance/governance_action_engine.py): Mediates mutation requests, validates inputs against the TransitionRegistry, commits state shifts, and blocks unauthorized transitions.
    • TransitionRegistry (src/cas_runner/governance/governance_action_engine.py): Maintains declarative lifecycle state graphs, valid paths, and transition preconditions.
    • Governance Models & Action Descriptors (src/cas_runner/governance/models.py): Defines structured representations of actions (GovernanceAction) and domain-level errors (GovernanceException).
    • Artifact Store: Persists lifecycle states and historical records for architectural entities.

    Technology choices

    • Declarative In-Memory State Registry: Implemented via native language data structures (enums, typed dictionaries) for fast, zero-dependency in-process verification.
    • Strict Typing & Contracts: Pydantic / Python dataclasses enforce contract integrity for incoming actions.
    • Considered and Set Aside: Heavyweight BPMN engines (e.g., Temporal, Camunda) were set aside to eliminate unnecessary network hops and infrastructure overhead for synchronous governance checks.

    Variants

    • Strict Synchronous Guard: Rejects invalid transitions immediately with explicit exceptions.
    • Dry-Run Evaluator: Exposes preview capabilities to allow agents to simulate actions without persisting state.
    • Hook-Augmented Enforcer: Triggers policy checks or security scanning webhooks prior to transition commit.

    Non-functional characteristics

    • Reliability: Eliminates invalid states through deterministic boundary checks and transactional commits.
    • Performance & Latency: Sub-millisecond lookup and validation overhead.
    • Cost & Efficiency: Runs embedded in existing application processes without dedicated infrastructure spend.
    • Operability: Emits typed GovernanceException structures and comprehensive audit logs for debugging and tracking.

    Anti-patterns & known pitfalls

    • Direct-Write Bypass: Bypassing the engine to write directly to persistence layers. Remedy: Enforce encapsulation through service boundaries.
    • Wildcard State Transitions: Allowing open-ended * -> * transitions. Remedy: Define explicit source and target state pairs.
    • Deadlock Terminal States: Introducing intermediary states lacking exit transitions. Remedy: Run state graph validation suites to confirm path reachability.

    Adoption guidance

    • Starting Point: Formalize existing artifact states into an enum and configure permissible edges in TransitionRegistry.
    • Migration Path: Deploy engine initially in logging-only mode to capture baseline transition traffic, then enforce strict rejection.
    • Ownership: Enterprise Architecture Governance Team (ideas-to-life-cas).
