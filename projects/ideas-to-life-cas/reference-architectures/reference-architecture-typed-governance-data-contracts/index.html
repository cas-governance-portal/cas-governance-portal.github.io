    Reference Architecture: Typed Governance Data Contracts

    Purpose & when to use this

    Enforces strongly-typed, schema-validated domain models across agentic execution boundaries, state representations, governance findings, and diagnostic metrics. This guarantees data integrity, prevents silent schema drift, and eliminates runtime payload errors between heterogeneous LLM agents and deterministic downstream systems.

    When to use this

    • Heterogeneous agent pipelines where autonomous agents emit structured findings, metric events, or state transitions that must be consumed by deterministic subsystems.
    • Compliance, auditing, and governance platforms requiring strict, immutable data contracts for reporting, verification, and automated remediation.
    • Distributed systems requiring bi-directional validation (compile-time type checking and runtime schema parsing) across I/O boundaries.
    • Teams operating multi-agent workflows where unvalidated string or JSON payloads lead to parsing exceptions or silent state corruption.

    When NOT to use this

    • Highly dynamic, exploratory prototyping where domain entities evolve rapidly on a per-invocation basis and schema stability is undefined.
    • High-throughput ingestion pipelines of raw, unstructured streaming telemetry where parsing overhead of nested schema validators exceeds microsecond latency budgets.
    • Simple single-script utilities with trivial data structures and no external serialization boundaries.

    Components

    • Governance Domain Models (src/cas_runner/governance/models.py): Defines canonical Pydantic domain models including ResolutionResult, TraceableMetric, GovernanceInventory, GovernanceHealth, GovernanceThroughput, GovernanceRisks, ComplianceFinding, ComplianceMetrics, GovernanceException, and GovernanceAction.
    • Contract Validation & Parser Layer (src/cas_runner/governance/validators.py): Ingests unstructured or semi-structured JSON outputs emitted by agents and applies strict parsing rules to guarantee conformity to the domain contracts.
    • Agent State Persistence Adapter (src/cas_runner/governance/persistence.py): Persists validated contract entities to state stores and handles schema version headers for state persistence and retrieval.

    Technology choices

    • Pydantic v2 (>=2.12.5): Selected for core model validation, high-performance Rust-backed deserialization, and native JSON schema generation.
    • Python Type Hints (PEP 484 / PEP 585 / PEP 604): Enforces static analysis through MyPy / Pyright across the codebase.
    • Alternatives Considered & Set Aside:
    • Standard Library dataclasses: Lacks automatic runtime type coercion, deep nested validation, and JSON serialization helpers.
    • Marshmallow / Attrs: Slower runtime throughput compared to Pydantic v2 core and weaker static type inference in modern IDEs.
    • Raw JSON Schema / jsonschema: Requires manual mapping between dictionary lookups and language-level types, failing to provide compile-time safety.

    Variants

    • Strict Validation Mode: Rejects unknown fields, enforces exact type matches, and immediately halts pipeline execution on schema deviation (used in audit and compliance pipelines).
    • Permissive / Evolution Mode: Allows extra payload attributes for non-breaking forward compatibility while validating required governance core attributes.
    • Streaming Validation Variant: Validates partial JSON output chunks from streaming LLMs using incremental schema reconstruction before final persistence.

    Non-functional characteristics

    • Reliability: Eliminates runtime TypeError and KeyError exceptions across inter-service agent boundaries through upfront parsing and deterministic contracts.
    • Performance & Latency: Sub-millisecond validation latency per record leveraging Pydantic v2 pydantic-core Rust implementation.
    • Cost & Efficiency: Minimizes wasteful downstream LLM execution by failing fast on invalid output tokens before triggering subsequent workflow nodes.
    • Operability: Emits machine-readable validation errors with precise field path locations (loc) and input context, simplifying pipeline debugging and automated retry handling.

    Anti-patterns & known pitfalls

    • Dict-Passing Anti-Pattern: Passing arbitrary dict[str, Any] instances across governance boundaries instead of concrete domain model instances.
    • Silent Coercion / Suppression: Using blanket try/except Exception blocks that swallow validation failures and default missing fields to null without audit trails.
    • Unversioned Model Divergence: Mutating model definitions without backwards-compatible default values or explicit migration schemas, breaking legacy persisted states.

    Adoption guidance

    1. Identify critical inter-module boundaries where agents emit findings, state changes, or metrics.
    2. Standardize all data payloads to inherit from canonical Pydantic models defined in src/cas_runner/governance/models.py.
    3. Integrate schema validation checks into automated unit tests and CI linters (e.g., mypy --strict).
    4. Establish schema versioning protocols using semantic version fields to support backwards-compatible schema evolutions.
