    Reference Architecture: Evidence-Driven Knowledge Promotion Pipeline

    Purpose & when to use this

    The Evidence-Driven Knowledge Promotion Pipeline establishes an explicit, auditable progression model that advances empirical architectural insights across four lifecycle stages: raw signals, structured experiments, context-bound heuristics, and formalized enterprise patterns. It prevents premature codification of architectural assertions by ensuring that recommendations adopted across teams are backed by verifiable implementation evidence and governance sign-off.

    When to use this

    • When operating multi-agent or multi-team software engineering organizations where design practices emerge organically across distributed codebases.
    • When central architectural repositories (e.g., ADR registries, architectural patterns) suffer from speculative design, unverified dogma, or pattern bloat.
    • When automated agents or developer tooling require high-fidelity, verified ground-truth patterns rather than subjective rules-of-thumb.
    • When enterprise governance mandates end-to-end provenance and verifiable evidence before declaring a pattern an organizational standard.

    When NOT to use this

    • In early-stage greenfield prototyping or single-team codebases where rapid exploration out-prioritizes formal knowledge governance.
    • In static technical domains where architectural standards are strictly mature, industry-standardized, and rarely evolving.
    • When documentation friction could paralyze development speed in crisis response or transient proof-of-concept projects.

    Components

    • Signal Capture Component (cas-knowledge/signals/): Ingests raw operational observations, agent failure modes, and recurring implementation anomalies from codebases.
    • Experimentation Engine (cas-knowledge/experiments/): Structures hypothesis-driven investigations to test emergent practices across isolated codebases, capturing empirical run metrics.
    • Heuristic Formulator (cas-knowledge/heuristics/): Maintains context-specific, provisional design guidance and rules-of-thumb that have proven effective in limited scopes.
    • Promotion Gatekeeper (cas-knowledge/templates/heuristic-to-pattern_template.md): Evaluates promotion criteria including significance, reusability, evidence quality, governance maturity, and strategic alignment.
    • Enterprise Knowledge Git Store (cas-knowledge/patterns/): Serves as the immutable version-controlled repository of record for formalized global reference architectures.

    Technology choices

    Document Architecture & Versioning

    • Selected: GitOps with structured Markdown and YAML frontmatter (cas-knowledge).
    • Rationale: Leverages distributed version control, cryptographic commit signatures, standard pull-request review pipelines, and branch protection to govern architectural assets without dedicated infrastructure overhead.
    • Alternatives Set Aside: Dedicated Knowledge Management CMS / Confluence (rejected due to disconnect from developer and agent workflows, inability to enforce automated schema linting in CI/CD, and lack of atomic versioning alongside code).

    Schema Validation

    • Selected: JSON Schema validation via GitHub Actions linters.
    • Rationale: Automatically validates metadata consistency, required evidence fields, and template conformity prior to human architectural review.
    • Alternatives Set Aside: Manual peer-review checklists (rejected due to inconsistent enforcement and risk of subjective gate bypass).

    Variants

    Agent-Assisted Lifecycle Mode

    Automated discovery agents monitor code repositories for recurring implementation motifs, automatically generating signal and experiment markdown drafts, followed by automated promotion candidate generation when adoption thresholds are reached.

    Human-in-the-Loop Governance Mode

    Domain architects manually synthesize findings from incident post-mortems and multi-repo retrospectives, authoring explicit promotion decision records (promotion_decision.md) for Architecture Review Board evaluation.

    Fast-Track Compliance & Security Variant

    Allows bypass of prolonged empirical experimentation stages when emerging security vulnerabilities or regulatory mandates demand immediate codification of enterprise-wide architectural constraints.

    Non-functional characteristics

    Reliability

    • High determinism through strict markdown schema enforcement and declarative promotion decision artifacts.
    • Complete lineage tracking ensures any global pattern can be traced back to its underlying heuristic, experiment, and original signal.

    Performance & Latency

    • Asynchronous knowledge progression decoupled from runtime application latency.
    • CI schema linting and promotion pipeline execution completes within seconds on standard runners.

    Cost & Efficiency

    • Zero dedicated runtime server costs by utilizing static repository files and native Git provider automation.
    • Drastically lowers engineering waste by preventing duplicated exploratory efforts across teams.

    Operability

    • Clear human-readable diffs for all knowledge stage transitions.
    • Auditable decision trails via standardized promotion_decision.md records prevent silent policy drift.

    Anti-patterns & known pitfalls

    The Heuristic Swamp (Promotion Stagnation)

    • Anti-pattern: Knowledge documents stall indefinitely in the heuristic phase without graduation or retirement because no explicit evaluation trigger exists.
    • Remedy: Implement scheduled quarterly promotion review intervals or automated adoption counters that trigger promotion evaluations once a heuristic is referenced by more than three independent services.

    Unverified Dogma Escalation (Speculative Promotion)

    • Anti-pattern: Promoting subjective preferences or single-instance solutions directly to enterprise standards without documented empirical experiments.
    • Remedy: Enforce automated CI blockers requiring valid references to experiment records and verified production metrics in the promotion_decision.md dossier.

    Over-Automated Blind Promotion

    • Anti-pattern: Granting AI agents full autonomous permission to merge candidate patterns directly to global status without human architectural validation.
    • Remedy: Maintain a mandatory human Architecture Review Board approval step in branch protection rules for all reference architecture directories.

    Adoption guidance

    Starting Point

    1. Import the template suite from cas-knowledge/templates/ (heuristic-to-pattern_template.md, promotion_decision.md).
    2. Audit current architecture repositories and triage existing documents into signals, heuristics, or patterns.
    3. Establish CI pull-request linting using JSON Schema to enforce metadata compliance on candidate records.

    Migration Path

    • Phase 1: Knowledge Classification. Migrate existing ADRs and informal notes into explicit signals/ or heuristics/ folders based on verifiable evidence strength.
    • Phase 2: Gatekeeper Tooling. Implement automated PR validation checks that ensure all promotion pull requests contain fully populated promotion_decision.md forms.
    • Phase 3: Feedback Cadence. Connect post-incident reviews and production retrospectives as standard feeds into the signals/ intake.
