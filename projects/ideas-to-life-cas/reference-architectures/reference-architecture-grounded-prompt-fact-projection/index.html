    Reference Architecture: Grounded Prompt Fact Projection

    Purpose & when to use this

    Overview and Purpose

    The Grounded Prompt Fact Projection pattern deterministically extracts, normalizes, and packages verified repository deltas and architectural registers into strongly typed prompt facts. Its primary goal is to completely eliminate LLM hallucinations during automated governance, architectural review, and decision checks by guaranteeing that reasoning agents operate exclusively over verified capability diffs and historical rules rather than speculative inferences or raw, unparsed git diffs.

    When to use this

    • Automated architectural decision agents or governance verification workflows require factual grounds regarding code and metadata changes.
    • Large codebase diffs exceed standard LLM token window limits or introduce high contextual noise that degrades evaluation quality.
    • Auditable, deterministic LLM evaluation pipelines require reproducible prompt contexts with verifiable lineage back to AST nodes or version-controlled deltas.
    • Systems need to decouple the computational overhead of diff parsing and semantic verification from LLM prompt synthesis.

    When NOT to use this

    • Open-ended creative generation or exploratory brainstorming where precise structural correctness and architectural invariants are secondary.
    • Single-file trivial diffs or small scripting repositories where raw source text fits within token constraints without prompt noise.
    • Ad-hoc conversational interfaces that lack underlying access to structural ASTs, git revision graphs, or formal architectural state registers.

    Components

    • Delta Extraction Service (src/cas_runner/steering/models.py): Inspects commit ranges, pull requests, and file updates to extract concrete code deltas, AST node transitions, and capability changes.
    • Fact Projection Compiler (src/cas_runner/steering/models.py): Normalizes parsed deltas into typed PromptFact instances, filters irrelevant syntactical churn, and produces the consolidated SteeringRuntimeIndex.
    • Steering Runtime Index Store (.github/workflows/cas-build-steering-projection.yml): Maintains persistent, immutable serialized snapshots of architectural state and projected facts for downstream evaluation workflows.
    • LLM Decision Agent (src/cas_runner/steering/models.py): Ingests serialized prompt facts directly into strict prompt scaffolding to execute deterministic governance assessments without ungrounded hallucinations.

    Technology choices

    Technology Selections

    • Data Modeling & Validation: Pydantic / Python Typing (PromptFact, SteeringRuntimeIndex) was chosen to enforce schema guarantees at compile-time and runtime serialization boundaries.
    • Orchestration & Triggering: GitHub Actions (.github/workflows/cas-build-steering-projection.yml) chosen for event-driven generation on pull request and merge commits, ensuring projections stay current with the repository state.
    • Serialization Format: JSON/JSONL with deterministic key ordering, chosen for low-overhead ingestion by standard LLM contexts.

    Alternatives Considered

    • Dynamic Vector Search (RAG): Discarded for governance decision paths because semantic similarity search can retrieve out-of-date or peripherally related snippets while omitting critical breaking signature changes.
    • Raw Git Diff Injection: Discarded due to token context limits, high token consumption costs, and inability of language models to reliably parse large multi-file hunks without hallucinating implicit dependencies.

    Variants

    1. CI-Compiled Batch Projection

    Projections are compiled as static artifacts during automated pull request or branch build workflows. Downstream agents load pre-computed indices from storage caches, minimizing runtime latency during governance decisions.

    2. Ephemeral In-Memory Projection

    Invoked on-demand in local developer environments or interactive agent loops. Facts are extracted in real-time across working tree dirty buffers without writing persistent artifacts to CI pipelines.

    Non-functional characteristics

    Reliability

    • Guarantees factual determinism: identical code modifications consistently yield identical PromptFact structures.
    • Eliminates hallucination-driven governance false positives by bounding LLM decision inputs to verified changes.

    Performance & Latency

    • Projection compilation adds modest overhead in CI (< 30 seconds for standard pull requests).
    • Agent evaluation latency decreases significantly because prompt payloads are reduced by 60-80% compared to dumping raw source files or unpruned diffs.

    Cost & Token Efficiency

    • Compact fact representation minimizes prompt token usage, yielding major operational cost reductions across high-frequency CI review loops.

    Operability & Auditability

    • Every projected fact includes AST symbol anchors and source commit hashes, providing complete forensic traceability from LLM evaluation verdicts back to original source lines.

    Anti-patterns & known pitfalls

    Anti-Pattern 1: Raw Diff Dumping

    • Problem: Passing unparsed git diffs straight to the agent prompt.
    • Impact: LLM misses cross-file interface contracts, misinterprets line deletions, and exhausts context windows.
    • Remedy: Force diffs through AST parsing into structured PromptFact models before prompt construction.

    Anti-Pattern 2: Over-Pruning Semantic Dependencies

    • Problem: Slicing diffs too aggressively to save tokens, removing caller/callee context.
    • Impact: Decision agents evaluate changes in isolation and fail to catch cascading architectural breaks.
    • Remedy: Include typed dependency references within the PromptFact schema to capture adjacent interface contracts.

    Adoption guidance

    Migration Path

    1. Model Adoption: Import and configure PromptFact and SteeringRuntimeIndex models from src/cas_runner/steering/models.py.
    2. Pipeline Integration: Deploy .github/workflows/cas-build-steering-projection.yml into target repositories to automate fact compilation on commit triggers.
    3. Agent Binding: Update prompt compilation logic in decision agents to inject the projected index rather than invoking dynamic vector searches or raw file reads.
